Migrating to 26.6.3

Stricter wildcard matching for valid redirect URIs

Wildcards in valid redirect URIs are no longer allowed to extend the host name. A valid redirect URI such as https://example.com* previously also matched https://example.com.other.test/callback, because the wildcard was applied to the whole URI string.

Starting with this release the wildcard is only honoured in the path component of the redirect URI. Authorization requests that rely on the previous behaviour are rejected with an invalid redirect_uri error.

Review the clients whose valid redirect URIs contain a wildcard before the first path separator and replace them with an explicit host followed by a path wildcard, for example https://example.com/*.

Migrating to 26.4.3

Requests with non-normalized paths are rejected

Keycloak now rejects HTTP requests whose path is not normalized, for example paths that contain double slashes (//) or dot segments such as /./ or /../. Such requests receive a 400 Bad Request response instead of being processed.

Reverse proxies and client libraries that build request paths by string concatenation should be checked, and the generated URLs normalized before they reach Keycloak.

Migrating to 26.0.0

Legacy redirect_uri parameter of the logout endpoint removed

The legacy-logout-redirect-uri option, which allowed the redirect_uri parameter on the OpenID Connect logout endpoint, has been removed. Logout requests that still send the redirect_uri parameter are rejected.

Clients must use the post_logout_redirect_uri parameter together with the id_token_hint or client_id parameter, as defined by the OpenID Connect RP-Initiated Logout specification.

Role protocol mappers always produce multivalued claims

The User Realm Role and User Client Role protocol mappers always produce multivalued claims. The Multivalued setting of these mappers is no longer taken into account, so a role claim is always emitted as a JSON array, even when the user has a single role.

Applications that parsed the role claim as a single string value must be updated to handle a JSON array.
